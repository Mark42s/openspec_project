# travel-planner spec delta

## Added Requirements

### Requirement: 接入真实途牛供应商(火车/机票/酒店)
系统 SHALL 在配置 `TUNIU_API_KEY` 时,通过途牛 MCP 开放平台检索真实火车票、机票与酒店,并归一化为内部报价模型;响应 `is_mock=false` 且 `sources` 含 `tuniu`。

#### Scenario: 配置途牛凭证后发起规划
- **WHEN** 系统检测到 `TUNIU_API_KEY` 且用户发起规划
- **THEN** 交通与酒店候选用真实途牛数据填充(真实车次/航班号、票价、到发站/机场、酒店名与最低价),响应 `is_mock=false`、`sources=['tuniu']`

#### Scenario: 真实源可用时不混入 mock
- **WHEN** 途牛供应商可用(有凭证)
- **THEN** 交通/酒店候选只含真实途牛结果,不混入 mock 假车次/假酒店

#### Scenario: 交通报价含真实到发站/机场
- **WHEN** 途牛返回火车或机票
- **THEN** 归一化报价保留出发/到达站点(火车为出发站/到达站,机票为出发/到达机场与航站楼),供规划展示「怎么到达」

### Requirement: 出发日期解析锚定当前日期
系统 SHALL 在意图解析时向模型注入当前日期,并把解析出的早于今天的出发日期确定性滚动到最近的未来同月日,避免真实供应商因过去日期拒绝查询。

#### Scenario: 用户提到日期但未说明年份
- **WHEN** 用户提交「9月29日出发」等未含年份的日期
- **THEN** 系统按当前年份解析;若该日期已过则按明年解析

#### Scenario: 模型解析出过去日期
- **WHEN** 模型把出发日期解析为早于今天的日期(如年份猜错)
- **THEN** 系统保留月日、滚动年份直到日期不早于今天
