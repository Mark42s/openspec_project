## Context

全新 Python 项目(FastAPI),尚无任何代码。动机见 proposal.md。约束:
- 比价价值在于「确定性并发查多源」,不是让模型自由探索;
- 实时价格时效强,但本期仅做「查一次 + 留快照」,不做自动下单;
- 真实国内供应商(途牛/美团)需要凭证,个人开发环境常不具备,必须能无凭证跑通全链路。

## Goals / Non-Goals

**Goals:**
- 端到端可跑:`自然语言 → 结构化行程建议`,无凭证用 mock 数据源也能完整走通并出可测 JSON。
- 受控成本:把 LLM 调用收敛到「意图解析」「汇总建议」两个小步骤,单次规划 token 用量可预估(约十几 k 输入量级),结构上排除模型反复自主调工具的放大效应。
- 可扩展:供应商以统一接口接入,后续真实凭证就位即可替换 mock,不改上层。

**Non-Goals:**
- 不做自主 agent 循环、不做价格预测与「何时买最优」建议、不做下单/支付/退改、不做多仓库 store 编排。
- 本期只接一家真实数据源方向(国内);海量源横向扩展留待后续。

## Decisions

**D1. 受控两段式 workflow,而非自主 agent。**
每次 `/api/plan` 只做两步模型调用:① 用轻量模型(默认 Sonnet,可降 Haiku)把自然语言解析成结构化约束(structured output 强 schema);② 检索聚合完成后,用主模型(Sonnet,复杂场景可升 Opus)读压缩后的 top-N 候选做多目标权衡,输出建议。
*为何*:旅行规划候选空间是确定形状的(日期×城市×供应商),确定性并发查询比让模型逐个调工具更准、更便宜、可复现;省 token 的原理是避免 agent 每轮把不断变长的历史整段重发。*替代考虑*:真让模型自己查(MCP agentic)——灵活但成本高一个量级且结果难复现,否决。

**D2. 供应商适配层 `SupplierAdapter` 抽象 + mock 兜底。**
统一方法签名(如 `search_transport()` / `search_hotel()` 返回归一化 pydantic 模型)。`mock.py` 提供确定性假数据;`tuniu.py` 为真实途牛接入占位,凭据不存在/调用失败时自动回落到 mock。后续美团等按同一接口新增。
*为何*:凭证缺失不阻塞开发与 CI;接口隔离使真实源接入是纯增量。*替代*:直接把 MCP 客户端写死在业务里——难测试,否决。

**D3. 结构化约束/响应用 pydantic + Anthropic structured output(`output_config.format`)。**
保证解析层输出严格 schema,下游检索无需容错脏 JSON;汇总建议也输出结构化行程(车次、酒店、日预算、理由、风险提示)。
*为何*:travel 软件下游要的是可编程 JSON,不是散文。

**D4. 价格历史用 SQLite(stdlib `sqlite3`),不引 ORM。**
单表 `price_snapshots`(约束哈希、类别、供应商、标识、价格、币种、采集时间)。本期只插不查,为未来走势分析留底。
*为何*:零额外依赖、零运维,适合单机部署起步。

**D5. 模型选择留配置,默认 Sonnet / 意图步骤可降 Haiku。**
成本敏感路由(意图解析)建议 Haiku/Sonnet;质量敏感路由(汇总)默认 Sonnet、可升 Opus。都由环境变量切换,不在代码里硬编码。
*为何*:两类任务的难度/成本诉求不同;单一模型最简,但多档配置避免日后为改模型改代码。*权衡*:多模型会拆缓存命名空间,量小可忽略。

## Risks / Trade-offs

- **价格不保证真实可用/一致性**:mock 是假数据,真实源上线前不能作为购买依据。→ 缓解:响应带 `sources:[...]` 与 `is_mock` 标记;README 免责声明「以实际下单页为准」。
- **真实供应商接入可能遇反爬/限流/凭证门槛**:本期不处理,`tuniu.py` 抛错即回落 mock。→ 缓解:适配层隔离,接入策略(官方 MCP/分销 API)作为后续独立变更设计。
- **LLM 汇总可能给出误导性「最优」**:模型只读已去重压缩候选,预算不足场景由 schema 强制给出显式提示(见 specs)。
- **token 波动**:结构化输出 + 大候选集输入可能超预算。→ 缓解:候选在进模型前做规则初筛截断 top-N;两步骤均设 `max_tokens` 上限。
- **OpenSpec 引擎对 spec 语法严格**(场景必须 4 个 `#`,否则 validate 静默失败):→ 缓解:写完后跑 `openspec validate` 把关。

## Migration Plan

绿地项目,无历史迁移。落地顺序:
1. 依 tasks.md 实现 `app/`(mock 源)与 `tests/`,本地 `pytest`+`ruff` 通过;
2. 提供 docker-compose/CI 交付物(本机无 Docker,由有 Docker 环境或 GitHub Actions 验证);
3. 真实途牛凭证就位后,独立变更启用 `tuniu.py` 并逐步关闭 mock 标记。
回滚:单服务可整体下线或切回上一镜像;数据库仅含快照,无破坏性。
