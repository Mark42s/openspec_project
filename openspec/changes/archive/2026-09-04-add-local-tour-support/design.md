## Context

解析层原本把"目的地缺失"视为不可规划;用户实际表达「出发地去周边自驾」是一种有意的开放玩法(design 于本变更修订)。修改点见 proposal.md。

## Goals / Non-Goals

**Goals:** 周边游需求端到端可用:解析不报 422,按出发地本地规划,费用不含长途交通;启发式与 LLM 两路径一致;真实高德 POI 可查(如苏州)。
**Non-Goals:** 郊县/邻市具体推荐与"周边 50km"空间语义、多城市串联、真实交通。

## Decisions

**D1. 用显式字段 `local_tour` 标记周边意图**,而非依赖目的地列表 hack。**为何**:下游(main/规划)需要判断"同城但非城际",语义清晰。
**D2. 周边关键词用固定规则表**(周边|自驾|附近|省内|近郊|开车去),意图归并到"以出发地为中心"。**为何**:启发式确定性、可测;复杂 NLU 语义留给 LLM 路径且 prompt 已含同规则。
**D3. 交通侧处理在聚合后**:main 发现 local_tour 即清空 transport(快照/规划/cost 一律按 0 长途)。**为何**:避免同城还出"苏州→苏州"车次的可笑结果,集中在入口处处理最简单。
**D4. 城市词表扩充到常见 60 城**以提升启发式出发地识别率。**权衡**:纯启发式的固有局限,配合真实 LLM 时几乎不受影响。

## Risks / Trade-offs

- 启发式"周边"触发依赖出发地先被识别 → 城市表扩充缓解;LLM 路径可兜底。
- 周边游没有真实"距离/区域"概念,推荐仍是市内 POI → 属 Non-Goal,后续可做"城市+邻市"范围。
- mock 下苏州无内置名单 → 高德 key 已配,真实 POI 检索生效;未配 key 时返回通用地标(仅占位)。

## Migration Plan

无破坏性迁移:新增可选字段与语义分支,旧输入行为不变(明确目的地仍走城际)。
